# Build 362 — Production Learning & Autonomous Roadmap Renewal

## Purpose

Build 362 closes the 351–361 learning cycle and converts what YW can now observe into the next bounded autonomous release sequence. This is a planning/evidence release: it does not create a parallel business authority, enable provider mutation, post Finance transactions, send customer communications, or relax release controls.

## Renewal principles

1. Prefer measurable operator, reliability, seasonal, economic, or data-quality outcomes over release-number churn.
2. Use existing canonical Jobs, Safety, Equipment, Employment, CRM, Finance, Dispatch, recurring-service, workability, inventory, and release-evidence authorities before creating new storage.
3. Where an outcome journal is required, record only the decision/outcome metadata needed for learning; never duplicate the source business record.
4. Keep spring/summer landscaping and lawn work, fall cleanup/leaf work, winter snow/storm/ice operations, and general four-season functions explicit.
5. Do not require external provider credentials, real payments, real customer messages, staging acceptance, or manual signoff to complete ordinary autonomous roadmap items.
6. Keep Finance posting, payment-provider mutation, external Auth controls, provider delivery, and destructive data reconciliation fail-closed unless separately authorized and evidenced.
7. Every future release must preserve exact-source release evidence, permission enforcement, mobile accessibility, and offline conflict ownership.
