MASTER363-YW-SOURCE-CONVERGE — independent source-bound Ed25519 handoff

  - Public discovery manifest: public/.well-known/rosevear-integration-manifest.json
    (the tracked source_revision is the known base YW557 revision). During Vercel
    production build on Git branch main, build-vercel-site writes the actual
    VERCEL_GIT_COMMIT_SHA to deployed dist/.well-known manifest and health.json.
    No valid Git deployment SHA -> null source_revision and explicit HOLD.
    This avoids the impossible self-referential commit-hash-in-own-file problem.
  - Independent custodian must already hold a real encrypted Ed25519 source key
    outside this repository, plus an independently enrolled and authenticated
    SHA256 fingerprint pin. Neither CI nor GitHub may create a substitute signer.
  - After exact main deployment, independently GET deployed public manifest,
    verify source_revision equals the production Git commit SHA, obtain its
    SHA256 digest, and run on the ORIGINAL SECURE SOURCE HOST:
      YWI_SOURCE_SIGNER_KEY_FILE=<private external file>
      YWI_SOURCE_SIGNER_PASSPHRASE=<local operator secret>
      YWI_TRUSTED_SOURCE_PIN_SHA256=<independently enrolled public pin>
      node scripts/master363-yw-source-converge-558.mjs sign <40-hex main SHA> <64-hex deployed manifest SHA256>
    Do not paste secrets into chat, shell history, tickets or repository.
    It outputs only a source-bound signed JSON packet and verification summary.
  - AI Data Platform Build364 independently verifies the signer enrollment PIN,
    signature, source revision, runtime evidence and freshness. The legacy
    `sign` packet uses the source-side envelope and is NOT accepted as a Build364
    convergence receipt. The public source proof packet alone does NOT verify
    original custodian identity, production host, approval, runtime connectivity
    or owner acceptance.

  - Build364 exact receipt contract (after independent signer enrollment):
    schema=rosevear.ai-data-platform.source-convergence-receipt.v1,
    handoffToken=MASTER363-YW-SOURCE-CONVERGE, sourceId=yw,
    sourceAppId=yard-workers, repository=RosevearCreations/yw,
    sourceRevision=manifestRevision=health.revision=exact production main,
    receiptVersion=1; health.state must be genuinely HEALTHY with fresh source
    runtime identity and observedAt. The protected source host must create a
    fresh out-of-repository JSON health observation containing:
      {"manifestSha256":"<64-hex digest of deployed manifest>",
       "manifestRevision":"<40-hex live source_revision>",
       "health":{"state":"HEALTHY","revision":"<same source_revision>",
                 "observedAt":"<fresh ISO timestamp>",
                 "sourceRuntime":"<real verified source runtime>"}}
    This observation must be obtained from actual independently checked source
    runtime, not inferred from a GREEN build, static health file or deploy READY.
    Then, on the ORIGINAL SECURE SOURCE HOST, with the independent public key
    pin pre-enrolled on the controller side, set YWI_SOURCE_SIGNER_KEY_ID to

      node scripts/master363-yw-source-converge-558.mjs sign-build364 <production main SHA> <deployed manifest SHA256> <external verified observation JSON file>
    Existing YWI_SOURCE_SIGNER_KEY_FILE, YWI_SOURCE_SIGNER_PASSPHRASE, and
